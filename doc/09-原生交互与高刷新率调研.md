# 原生交互与高刷新率调研

日期：2026-11-14。先研究再修改；本轮以旧 Launchpad 的官方行为、本机 LaunchOS 2.5.0 的可见行为和 Apple 渲染 API 为依据。

## 证据及局限

- [Apple macOS 15 Launchpad 指南](https://support.apple.com/en-ie/guide/mac-mini/aside/apd2d2a58738/2024/mac/15)：网格拖动排序、应用叠放建文件夹、拖入／拖出、双指分页。未公布悬停范围、延迟或动画曲线。
- [LaunchOS 作者说明](https://github.com/Remix-Design/LaunchOS/blob/main/README.md)：V2 从 SwiftUI 迁移到 AppKit，支持 120Hz+。本机版本 Info.plist 为 2.5.0；其二进制链接 AppKit、QuartzCore 和 SwiftUI，仅凭依赖不能推断具体私有实现。没有读取或复制其源代码、布局数据库或许可证信息。
- 本机 CUA 观察：主页面大图标网格；文件夹展开后主网格退场，标题居中于展开区上方；搜索变 disabled；点击面板外关闭文件夹并恢复搜索，Esc 收起。截图不能测定时长、速度曲线或实际 FPS，因此不能将它当作逐帧测量。
- [AppKit displayLink](https://developer.apple.com/documentation/appkit/nsview/displaylink(target:selector:)) 和 [WWDC23](https://developer.apple.com/videos/play/wwdc2023/10054/)：显示同步应绑定所在 view/window，会跟随显示器切换，不应使用固定 60Hz Timer。
- [CAAnimation.preferredFrameRateRange](https://developer.apple.com/documentation/quartzcore/caanimation/preferredframeraterange)：可以向系统请求刷新率，实际仍取决于显示设备与系统调度；iPhone 专用 Info.plist 键不适用于 Mac。
- [Apple hitch 分析](https://developer.apple.com/documentation/xcode/understanding-hitches-in-your-app)：要区分 app commit 和 render server 的超时；“感觉 60 帧”不足以证明固定帧率上限。

## 当前实现的具体问题

- 离散滚轮被按连续位移处理，需要累计到页宽的 18%，导致一格不翻页。
- 鼠标位移、滚动 delta 混用不同符号；必须各自转换到“内容向左移动 → 下一页”的统一坐标。
- 关闭前先恢复窗口层级与系统栏，窗口可能已经掉到其他窗口后面；重复失活通知还会取消关闭任务。
- SwiftUI Animatable 页变换会在过渡帧重走视图更新路径；不应把所有页的位移交给整个视图树刷新。
- 文件夹前后两套网格复用输入，父层 allowsHitTesting 不足以防御所有路径；业务层必须再次校验可激活项，遮罩必须真正消费按下和抬起。
- 插入线不等于实时排位预览；悬停期间应修改仅驻内存的预览布局，落下提交、取消回滚，禁止每次移动写盘。

## 实施原则与参数

高频分页使用 AppKit 承载稳定页视图、Core Animation 图层变换，用户输入阶段直接跟随，吸附阶段用 CAAnimation；按当前屏幕 maximumFramesPerSecond 请求刷新率，不固定 60。空闲不额外维持计时器。

离散滚轮一格立即选择相邻页；连续触控板 delta 与鼠标拖动分别转换方向。关闭先完成可见动画，再恢复系统展示。文件夹使用真正模态的内容层，背景主网格不接收鼠标、键盘、滚轮激活。

排序使用预览布局和实际占位，取消恢复。新建文件夹与加入既有文件夹分开处理：既有文件夹中心落点可直接接受；新建成组保留短暂停留并使用同一中心命中范围。选定的停留时间与曲线属于 Sunny 的可调实现参数，不能宣称是 Apple 的精确数值；后续应在 macOS 15 实机高帧录屏对照。

## 菜单栏与 Dock 的独立覆盖（2026-11-14）

本机 LaunchOS 2.5.0 的 arm64 二进制引用了 `_CGSSetMenuBarInsetAndAlpha`、`_CGWindowListCopyWindowInfo`，字符串中可见 `MenuBarManager`、`menuBarTimer` 和 `lastMenuBarAlpha`。这些只能证明符号或字符串存在，不能证明具体调用时机及设置语义；前者属于未公开的 Core Graphics 符号，不作为 Sunny 的实现依赖。

[Apple 的 NSApplication presentationOptions 文档](https://developer.apple.com/documentation/appkit/nsapplication/presentationoptions-swift.struct)明确规定 hideMenuBar 必须同时 hideDock，autoHideMenuBar 也必须搭配 hideDock 或 autoHideDock。Sunny 用窗口层级遮住菜单栏，并依据 visibleFrame 留出 Dock 区域；选择覆盖 Dock 时才设置 hideDock。默认覆盖菜单栏、不覆盖 Dock。Dock 位于左侧或右侧时，单一矩形窗口会同时保留该侧菜单栏对应的窄条区域；不同显示器、自动隐藏 Dock 与 Spaces 的实际表现仍需验证。
