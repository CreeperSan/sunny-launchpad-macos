# 旧版 Launchpad 功能与交互调研

调研日期：2026-11-13。体验基线：macOS Sequoia 15 的 Launchpad；不追求复刻 Tahoe 的 Spotlight Apps。

## 一、可确认的产品行为

Apple 的 [Mac mini / macOS 15 Launchpad 指南](https://support.apple.com/en-ie/guide/mac-mini/aside/apd2d2a58738/2024/mac/15) 明确描述：

| 场景 | 旧版行为 | Sunny 对应设计 |
| --- | --- | --- |
| 打开与关闭 | Dock 图标打开；Esc 或图标以外区域关闭 | Dock 再次激活、菜单栏入口、独立全屏覆盖窗口 |
| 浏览 | 应用按网格排列，支持多页 | 有序页面模型，底部页码圆点 |
| 翻页 | 双指滑动；Command + 左右箭头 | 水平滚动手势、快捷键、页码点击 |
| 搜索 | 顶部输入应用名称 | 输入即过滤；搜索跨文件夹，不更改布局 |
| 排序 | 拖动应用到新位置 | 插入排序，跨页移动 |
| 文件夹 | 应用拖到另一应用上建文件夹；拖入添加；拖出移除 | 单层逻辑文件夹，有序子页面 |
| 新应用 | App Store 安装应用进入启动台 | 扫描应用目录，新增条目追加，不重排旧位置 |

以上仅概括官方可确认行为。视觉采用桌面壁纸模糊、大图标、居中名称、小搜索框；具体像素、缓动曲线和文件夹布局需后续在 macOS 15 实机逐帧对照。

## 二、需要区分的相似行为

- 旧版长按／Option 的抖动和可删除应用叉号：首版保留“整理模式”，但不提供实际卸载，避免把移除启动器条目误当成卸载。
- 文件夹可以命名，内容有顺序；不支持文件夹嵌套。本机数据库证实文件夹下还有页面层，不能简单按 folder → app 两层读取。
- 旧版系统支持触控板多指捏合、Launchpad 功能键与触发角。第三方 app 不能假定获得相同系统入口。第一阶段使用 Dock、菜单栏和 Control + Option + Space；多指全局手势、系统功能键替换另行验证，不启用私有框架。
- 自动分类、应用通知角标、App Store 下载进度、iPhone 镜像应用不是基础网格功能；首版不承诺系统级集成。
- 默认主网格和文件夹均采用 7 列 × 5 行。实测遗留库有单个文件夹页容纳 26 项，系统没有设置 springboard 行列覆盖，因此不能以 21 项强行拆开文件夹页；35 项容量可保留本机样本原分页。不同历史版本的精确像素仍待对照。

## 三、旧布局存储研究

技术参考采用作者研究与原始工程：[lporg](https://github.com/blacktop/lporg)、[数据库研究记录（实测 schema 部分）](https://github.com/0xdevalias/dotfiles/issues/7)。这些是非公开格式的研究，不是 Apple 兼容性承诺。未复制第三方实现代码。

本机遗留数据库的副本实测：

- 路径模式：`$(getconf DARWIN_USER_DIR)com.apple.dock.launchpad/db/db`。
- 部分环境 `getconf` 失败，可由用户临时目录的同级 `0` 目录寻找；也支持用户手选备份。
- 较老位置：`~/Library/Application Support/Dock/*.db`。不能把其中 `desktoppicture.db` 误认成布局。
- `items(rowid, uuid, flags, type, parent_id, ordering)` 保存层次与顺序。
- `apps(item_id, title, bundleid, ..., bookmark)` 保存应用身份。
- `groups(item_id, ..., title)` 保存文件夹名称。
- 本机类型：1 = root、2 = folder、3 = page、4 = app。
- 可见树起点是 UUID 为 `ROOTPAGE` 的节点；`ROOTPAGE_VERS`、`HOLDINGPAGE*` 是不同用途的内部节点，不能按全部 apps 表直接导入。
- 本机副本有 2 个可见主页面、11 个文件夹；apps 表共 161 项，其中部分位于版本暂存页，不属于可见布局。统计结果不附带私人应用清单。
- 排序按 `ordering`，同序使用 rowid 保持确定性。不能假定固定 rowid 代表根或第一页。

## 四、导入边界与风险

SQLite 官方说明：[只读连接](https://sqlite.org/c3ref/open.html)、[WAL 只读条件](https://sqlite.org/wal.html)、[在线备份](https://sqlite.org/backup.html)。只读 SQLite 连接仍可能创建／更新共享内存辅助文件，因此“只读打开原库”不足以满足本项目最严格的原数据隔离。

采用源文件普通只读读取 → 在私有临时目录复制 db 和可选 db-wal → 再次读取比对内容 → 对副本执行 SQLite 只读解析、quick_check、schema 校验。只要读取期间变化就拒绝并提示重试；不向源目录创建 shm，不执行 checkpoint、VACUUM、Dock reset 或 killall。该方案面向升级后静止的遗留库；不宣称对持续活跃写入的任意 SQLite 数据库提供在线事务快照。活跃源应先用原系统生成一致性备份，再手选导入。

导入预览列出页面、文件夹、匹配项和未安装占位项。只有点击应用后才更新 Sunny 自有布局，并先备份。缺失应用保留名字和位置，后续扫描能按 bundle ID 恢复；新安装但旧布局未包含的应用追加到后续页面。
